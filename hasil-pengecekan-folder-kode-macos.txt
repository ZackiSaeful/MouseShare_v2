5. PEMERIKSAAN A — SECURITY VULNERABILITY AUDIT (RINCIAN CELAH SISTEM)
--------------------------------------------------------------------------------

[A-01] Default Insecure Pairing Token ("CHANGE_ME") pada Konfigurasi CLI
- Lokasi        : mouseshare/mac/config.json (baris 4)
                  mouseshare/windows/config.json (baris 4)
- Jenis Masalah : Hardcoded Default Secret / Insecure Default Configuration
- Kategori      : HIGH
- Status        : CONFIRMED
- Bukti Kode    :
  "windows_host": "192.168.2.101",
  "port": 5555,
  "token": "CHANGE_ME",
- Analisis Teknis:
  File konfigurasi template bawaan menyertakan nilai token "CHANGE_ME". Pada aplikasi
  GUI (mouseshare_app.py), sistem secara otomatis memblokir token ini dan menolak pairing.
  Namun, jika pengguna menjalankan modul agen secara langsung melalui CLI:
  `python -m mouseshare.mac.mac_app` atau `python -m mouseshare.windows.windows_app`,
  konfigurasi config.json dibaca tanpa validasi penolakan "CHANGE_ME".
- Potensi Dampak:
  Penyerang pada jaringan Wi-Fi/LAN yang sama dapat memindai port 5555 dan melakukan
  autentikasi instan menggunakan token default "CHANGE_ME", mendapatkan kontrol penuh
  terhadap mouse dan keyboard Windows atau menyuntikkan input berbahaya.
- Rekomendasi:
  Hapus token default atau ganti dengan string kosong, dan tambahkan validasi penolakan
  token "CHANGE_ME" langsung di dalam mac_app.py dan windows_app.py.

[A-02] Transmisi Kunci Plaintext & Komunikasi Tak Terenkripsi pada Mode Legacy
- Lokasi        : mouseshare/secure_transport.py (baris 125-128, 136-147, 243-266)
                  mouseshare_app.py (baris 1359-1379)
- Jenis Masalah : Cryptographic Downgrade & Cleartext Key Transmission
- Kategori      : HIGH
- Status        : CONFIRMED
- Bukti Kode    :
  if allow_legacy_protocol:
      # A v1 server can authenticate only by receiving the pairing key in
      # clear text. Never send it to an encrypted v3 peer by default.
      hello["token"] = token
  ...
  return LegacyChannel(), False
- Analisis Teknis:
  Jika opsi `allow_legacy_protocol` diaktifkan oleh pengguna, fungsi `client_handshake()`
  akan menyertakan parameter `hello["token"] = token` secara terbuka dalam paket TCP
  pertama. Selain itu, sesi diturunkan ke `LegacyChannel` yang mengirimkan seluruh input
  keyboard, mouse, dan clipboard dalam bentuk JSON polos tanpa enkripsi AES-GCM.
- Potensi Dampak:
  Siapa pun yang menyadap lalu lintas jaringan lokal (melalui ARP spoofing, Wi-Fi tanpa
  enkripsi kuat, atau port mirroring) dapat membaca pairing token serta seluruh data yang
  diketikkan pengguna (termasuk password, pesan rahasia, kredensial login).
- Rekomendasi:
  Hapus sepenuhnya dukungan protokol v1 legacy atau pastikan mode legacy hanya dapat
  diaktifkan dengan peringatan keamanan berlapis (Security Warning modal).

[A-03] Kebocoran Kredensial via Automatic Clipboard Synchronization
- Lokasi        : mouseshare/clipboard_sync.py (baris 39-58, 210-221)
- Jenis Masalah : Sensitive Data Exposure / Insecure Clipboard Handling
- Kategori      : MEDIUM
- Status        : CONFIRMED
- Bukti Kode    :
  pool = AppKit.NSAutoreleasePool.alloc().init()
  try:
      value = AppKit.NSPasteboard.generalPasteboard().stringForType_(
          AppKit.NSStringPboardType)
      text = str(value) if value is not None else ""
  finally:
      del pool
- Analisis Teknis:
  `ClipboardSynchronizer` melakukan polling NSPasteboard setiap 250 ms. Kode hanya
  memeriksa apakah tipe data adalah `NSStringPboardType` dan panjangnya <= 48 KiB.
  Aplikasi TIDAK memeriksa metadata khusus pasteboard macOS yang umumnya disetel oleh
  Password Manager (1Password, Bitwarden, KeePass, Apple Keychain), seperti:
  - `org.nspasteboard.TransientType` (menandai data sementara)
  - `org.nspasteboard.ConcealedType` (menandai kata sandi rahasia)
  - `org.nspasteboard.AutoGeneratedType` (menandai kode OTP / token)
- Potensi Dampak:
  Setiap kali pengguna menyalin password master, kunci privat SSH, kartu kredit, atau
  token 2FA di Mac, data tersebut langsung ditransmisikan dan disalin ke clipboard Windows.
  Jika komputer Windows digunakan bersama atau tidak terkunci, kredensial tersebut bocor.
- Rekomendasi:
  Tambahkan pengecekan tipe metadata NSPasteboard. Abaikan sinkronisasi jika pasteboard
  mengandung `org.nspasteboard.TransientType` atau `org.nspasteboard.ConcealedType`.

[A-04] Penyimpanan Pairing Token Plaintext pada Disk Lokal (settings.json)
- Lokasi        : mouseshare_app.py (baris 111, 200-216, 1519-1545)
- Jenis Masalah : Insecure Credential Storage
- Kategori      : MEDIUM
- Status        : CONFIRMED
- Bukti Kode    :
  fd = os.open(temp_path, os.O_WRONLY | os.O_CREAT | os.O_TRUNC, mode)
  with os.fdopen(fd, "w", encoding="utf-8") as stream:
      stream.write(json.dumps(self.settings, indent=2))
- Analisis Teknis:
  Token pairing (`client_token` dan `server_token`) disimpan dalam bentuk plaintext JSON
  di path `~/Library/Application Support/Mousehare/settings.json`. Meskipun direktori diberi
  izin `0o700` dan file `0o600` di macOS, token tidak disimpan di Apple Keychain.
  Di Windows, file ditulis dengan mode `0o666` yang bergantung pada inherit DACL sistem.
- Potensi Dampak:
  Setiap aplikasi atau skrip yang berjalan di bawah akun pengguna yang sama dapat membaca
  file `settings.json` dan mengekstraksi token pairing tanpa otorisasi tambahan.
- Rekomendasi:
  Gunakan macOS Keychain Services (via modul Security / Keyring) untuk menyimpan token
  pairing di macOS, dan DPAPI / Windows Credential Manager di Windows.

[A-05] Potensi Arbitrary Input Injection Akibat Karakteristik Arsitektur KVM
- Lokasi        : mouseshare/windows/windows_app.py (baris 635-698)
- Jenis Masalah : Architectural Remote Input Injection Primitive
- Kategori      : MEDIUM
- Status        : CONFIRMED (Design Primitive)
- Bukti Kode    :
  if action == "press":
      _kb.press(key)
  else:
      _kb.release(key)
- Analisis Teknis:
  Aplikasi ini pada dasarnya adalah Remote Virtual KVM. Sisi server menerima instruksi
  keyboard dan mouse dari sisi client dan menyuntikkannya ke OS menggunakan Win32 / pynput.
  Tidak ada mekanisme sandbox atau konfirmasi pengguna untuk aksi berbahaya (misalnya
  penekanan tombol Win+R dilanjutkan dengan string perintah powershell).
- Potensi Dampak:

  keyboard layaknya serangan BadUSB / Rubber Ducky.
- Rekomendasi:
  Pertahankan enkripsi AES-GCM secara absolut (nonaktifkan fallback legacy), pertimbangkan
  opsi pembatasan hotkey kritis di sisi penerima jika diinginkan.

[A-06] Binding Interface Jaringan 0.0.0.0 pada Template Konfigurasi Server
- Lokasi        : mouseshare/windows/config.json (baris 2)
                  mouseshare/windows/windows_app.py (baris 844-855)
- Jenis Masalah : Insecure Network Interface Binding
- Kategori      : LOW
- Status        : CONFIRMED
- Bukti Kode    :
  "host": "0.0.0.0",
  "port": 5555,
- Analisis Teknis:
  Template default menetapkan `"host": "0.0.0.0"`. Di windows_app.py ada proteksi pencarian
  rute LAN menggunakan socket probe ke 192.0.2.1, namun jika probe gagal, server akan bind
  ke semua antarmuka jaringan (termasuk antarmuka publik atau VPN).
- Potensi Dampak:
  Layanan port 5555 berpotensi dapat diakses dari jaringan selain LAN privat.
- Rekomendasi:
  Batasi binding secara eksplisit hanya pada IP LAN adapter yang dipilih pengguna.

[A-07] Ad-hoc Code Signing & Penonaktifan App Sandbox pada Bundle macOS
- Lokasi        : scripts/build-macos.sh (baris 45-53)
                  dist/Mousehare.app/Contents/Info.plist
- Jenis Masalah : Missing Entitlements, Ad-hoc Signature & Missing Hardened Runtime
- Kategori      : LOW / INFORMATIONAL
- Status        : CONFIRMED
- Bukti Kode    :
  codesign --force --deep --sign - --identifier com.mousehare.desktop "$APP"
- Analisis Teknis:
  Aplikasi di-bundle menggunakan penandatanganan ad-hoc (`--sign -`) tanpa Developer ID.
  Di macOS, CDHash binary ad-hoc berubah setiap kompilasi ulang, menyebabkan macOS TCC
  mereset izin Accessibility dan Input Monitoring. Selain itu, flag `--deep` digunakan
  (Apple mengimbau menghindari `--deep` karena dapat merusak penandatanganan nested library).
  Aplikasi juga tidak memiliki sandbox (com.apple.security.app-sandbox) karena CGEventTap
  memerlukan akses global.
- Potensi Dampak:
  Pengguna harus menyetujui ulang izin sistem pada setiap rebuild. Tanpa Hardened Runtime,
  proses rentan terhadap dylib injection dari aplikasi lokal lain.
- Rekomendasi:
  Gunakan sertifikat Apple Developer resmi dengan opsi `--options runtime` dan tandatangani
  framework secara eksplisit dari dalam ke luar tanpa `--deep`.

[A-08] Potensi Resource Starvation / Connection Slot Exhaustion
- Lokasi        : mouseshare/windows/windows_app.py (baris 832-840)
                  mouseshare/mac/protocol.py (baris 10, 43-54)
- Jenis Masalah : Potential Denial of Service (DoS)
- Kategori      : LOW
- Status        : POTENTIAL
- Bukti Kode    :
  _client_slots = threading.BoundedSemaphore(4)
- Analisis Teknis:
  Sisi server membatasi koneksi konkruen hingga 4 slot dengan timeout 10 detik per koneksi.
  Jika 4 koneksi TCP dibuka sekaligus oleh entitas lokal tanpa menyelesaikan handshake,
  klien resmi Mac akan tertahan selama 10 detik sebelum dapat mencoba kembali.
- Potensi Dampak:
  Gangguan ketersediaan layanan sesaat (temporary denial of service).
- Rekomendasi:
  Turunkan handshake timeout menjadi 3.0 detik dan implementasikan IP rate-limiting sederhana.
